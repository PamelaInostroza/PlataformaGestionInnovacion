# Seguridad, privacidad y publicación responsable

**Créditos de la implementación:** consulta [Créditos y contribuciones](../CREDITOS.md)

## Controles esperados

- Autenticación y autorización en el servidor.
- Permisos según perfil y ámbito organizacional.
- Secretos mediante variables de entorno.
- Cifrado de transporte.
- Validación de entradas.
- Auditoría de operaciones sensibles.
- Respaldos y procedimientos de recuperación.
- Políticas de acceso mínimo necesario.
- Revisión de dependencias y vulnerabilidades.

## Reglas para este repositorio público

No publicar:

- bases o archivos con información real;
- nombres, correos, identificadores o fotografías sin autorización;
- credenciales, tokens, variables de entorno o URLs privadas;
- diagramas con infraestructura sensible;
- reglas que faciliten evadir controles;
- código o recursos cuya propiedad no permita redistribución;
- capturas con información institucional identificable.

Las imágenes públicas deben usar datos ficticios y una marca demostrativa.

## Separación de responsabilidades

Los controles finales dependen del entorno de cada cliente. Antes de una implementación se deben acordar residencia de datos, responsables, retención, respaldo, respuesta ante incidentes y requisitos normativos.

## Revisión previa a publicar

- [ ] Todo dato es ficticio o está autorizado.
- [ ] No existen secretos en archivos ni historial.
- [ ] Las capturas fueron anonimizadas.
- [ ] La marca utilizada puede publicarse.
- [ ] La autoría diferencia contribución individual y colectiva.
- [ ] Los derechos sobre el código fueron revisados.
- [ ] Los datos de contacto son personales y deliberadamente públicos.
